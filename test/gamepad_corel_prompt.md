# ПРОМТ: фотореалистичный векторный геймпад Logitech F310 в CorelDRAW 27 через corel-mcp

WORKDIR = C:\work\gamepad   (замени на свой абсолютный путь; внутри должны быть папки ref\, svg\, shots\, work\, out\; референс лежит в ref\orig.jpg)

# 0. РОЛЬ И ЦЕЛЬ

Ты — агент-иллюстратор. Через MCP-сервер corel-mcp ты управляешь CorelDRAW 27 и рисуешь фотореалистичное векторное изображение проводного геймпада Logitech F310 по референсу WORKDIR\ref\orig.jpg (2000×1244 px, вид строго сверху, чисто белый фон).

Результат: WORKDIR\out\gamepad.cdr (векторный, слои, сгруппированные детали) и WORKDIR\out\gamepad_2000x1244.png.

Запрещено: вставлять в документ orig.jpg или любые растровые производные от него. Разрешено и нужно: измерять референс программно (раздел 4) и сверять с ним результат.

Это цель качества, а не гарантия возможностей MCP. При неподтверждённой векторности, недоступном референсе, невозможности соблюсти порядок перекрытия или провале критериев сообщи BLOCKED / NOT_ACCEPTED, сохрани только проверенные промежуточные результаты и не объявляй фотореализм достигнутым.

Подготовка файлов, запуск Python, вычисление SHA-256, чтение PNG и открытие сравнительных изображений выполняются инструментами хоста агента, НЕ CorelDRAW MCP. До рисования проверь их наличие, существование референса, его размер и доступность Pillow/numpy. Без этих средств сервер сам не измерит JPG, не создаст SVG/скрипты/журнал и не посчитает IoU. Не устанавливай зависимости и не меняй конфигурацию сервера без отдельного разрешения. Папки WORKDIR подготовь средствами хоста; проверь отсутствие выходных файлов, которые можно случайно перезаписать.

# 1. ЧТО УМЕЕТ СЕРВЕР (факты, от них зависит вся стратегия)

Контракт ниже сверён с реестром corel-mcp 0.4.0 (39 инструментов), схемами src/tools.ts, src/drawing-tools.ts, src/batch-tools.ts и реализациями worker/CorelMcp.Worker/Operations. Перед выполнением приоритет имеет tools/list именно подключённого сервера. Backend — C# STA worker; в hybrid часть операций использует фиксированный проверенный VBA runtime. Пользовательский код, произвольный VBA/COM и PowerShell сервер не принимает; переключать режим нельзя.

Доступные для этой задачи инструменты (имена точные):
- Документы: corel_status, corel_inspect_document, corel_create_document, corel_open_document, corel_save_document, corel_close_document.
- Геометрия: corel_create_shapes, corel_create_curve, corel_inspect_curve, corel_edit_curve, corel_transform_shapes, corel_duplicate_shapes, corel_grid_duplicate, corel_group_shapes, corel_boolean_shapes, corel_convert_to_curves.
- Слои/страницы: corel_manage_layers, corel_manage_pages. Перенос на слой — corel_manage_layers с action="move_shapes", отдельного move_to_layer нет.
- Оформление/текст: corel_style_shapes, corel_create_text, corel_edit_text, corel_find_text.
- Импорт/вывод: corel_import, corel_export, corel_preview; справка — corel_guide, corel_describe_api.
- Дополнительные операции: corel_align_shapes, corel_layout_shapes, corel_measure_shapes, corel_preflight, corel_powerclip. Для этой иллюстрации они не обязательны; PowerClip не использовать без отдельной проверки его ограничений.

Нет публичных операций задания/редактирования градиентной заливки, прозрачности, shadow/feather/contour/blend/mesh, произвольного удаления фигур/слоёв, установки выделения, перестановки слоёв или z-order фигур, трекинга/кернинга. Булевы операции могут удалить свои операнды согласно keep_left/keep_right, но не заменяют инструмент удаления. Слой выбирается по layer_id, не по индексу. corel_create_batch/corel_update_batch зарегистрированы в обоих режимах, но исполняются только при job.result.executor.execution_mode="hybrid" в ответе corel_status; до 1000 items и 100000 UTF-16 символов суммарно. В csharp используй обычные операции.

Следствие: градиенты и мягкие переходы готовятся в SVG и импортируются ТОЛЬКО после КТ-0b. Сам импорт не гарантирует сохранение оформления в векторе. Альтернатива — непрозрачные векторные фигуры со сплошными цветами (3.6). Каркас, текст, перемещение, группировка, сохранение и экспорт делаются типизированными инструментами.

## 1.1. Протокол вызовов

1. Читай MCP tools/list (это метод протокола, НЕ инструмент corel_tools_list). Получи inputSchema, затем corel_guide с темами skill, tools, operations, recipes, pitfalls; дочитывай next_offset. Если CorelDRAW-инструменты не подключены, запроси подключение/список/документацию и остановись. Не заменяй их инструментами другого приложения. corel_describe_api даёт метаданные установленного API, а не разрешение вызвать произвольный метод. Справка может содержать устаревшие примеры: не вызывай отсутствующие в tools/list инструменты.
2. Всем новым изменяющим вызовам назначай уникальный request_id длиной 1–200, например `RUN20261117_S7_btnY_001`; добавляй идентификатор запуска, чтобы не столкнуться со старым отчётом. Изменённые параметры требуют нового request_id. Слепой повтор с новым ID запрещён: прежний запрос мог уже примениться. При принятии COM-вызова возвращается job_id; при ошибке валидации/BUSY возможен только `{error:{code,message}}` без задания.
3. Распакуй `job = response.structuredContent`, либо JSON текстового блока content. Результат операции — `job.result`, ошибка — `job.error`, восстановление — `job.cleanup`, пути — `job.artifacts` (массив строк). Если `job.result.result_in_artifact=true`, прочти указанный JSON-файл `job.result.path` средствами хоста; не трактуй этот указатель как полную инспекцию.
4. Все COM-операции, включая status/inspect/preview/describe_api, асинхронны: опрашивай corel_get_job с `{job_id,wait_seconds:20}`. corel_guide отвечает сразу, без job. Допустимые status: running, timed_out, succeeded, failed, unknown. `partial` — НЕ status: проверяй `job.result.partial`, `error.applied`, `created_static_ids`, `affected_static_ids`, `deleted_static_ids`.
5. `running` — ждать. `timed_out` не завершает исполнение и не освобождает слот; продолжай наблюдать ТОТ ЖЕ job до фактического завершения. Для timed_out wait_seconds может возвращаться сразу: используй паузу/планирование ожидания хоста, не быстрый цикл. Не отправляй status/inspect/preview или новые мутации, пока исполнитель занят: они тоже могут получить BUSY. Не перезапускай сервер/worker ради освобождения слота.
6. Следующий COM-вызов допускается после наблюдаемого завершения предыдущего (`finished_at` и status succeeded/failed), но успех с cleanup.completed=false, failed/CLEANUP_FAILED, result.partial=true, error.applied=true/неизвестно требуют разбора отчёта и внеплановой проверки. Мутацию не повторяй. При unknown/потере worker останови рисование до выяснения исхода оператором; наличие finished_at само по себе не доказывает завершение потерянного COM-вызова.
7. В норме принятие этапа требует succeeded и cleanup.completed=true. При ошибке сначала зафиксируй job_id, error, известные ID, warnings и cleanup; inspect выполняй только когда исполнитель доступен. Отказ до мутации подтверждается error.applied=false и отсутствием наблюдаемой частичной мутации, а не одним названием ошибки.
8. Используй document_id из create/open/status; page_index (с единицы) и page_id из inspect; только рабочие layers с is_special_layer=false, editable=true. SDK StaticID в JSON называется `static_id`/`static_ids`, созданные ID — `created_static_ids`. Храни document/page/layer bindings и семантическую таблицу фигур в WORKDIR\work\ids.json. Нельзя выбирать объект по имени/первому индексу; имена слоёв лишь помогают подписать уже полученные ID. Полей имени фигуры/группы в create_shapes/group_shapes нет.
9. Save As и export молча заменяют файл; поля overwrite у этих двух инструментов нет. До вызова проверяй путь средствами хоста. Используй новые stage_NN_vN.cdr, SVG и PNG *_vN; итоговые gamepad.cdr/gamepad_2000x1244.png — только если они отсутствуют, иначе новые версии с явным отчётом.
10. Не вызывай Application.Quit, не завершай процессы CorelDRAW и не трогай чужие документы, объекты, GMS или общую среду. Не заявляй «нарисовано», «векторно» или «PASS» без доказательств инспекции и контрольного изображения.

## 1.2. Необратимость

Общего delete/undo/transaction нет. Правильные поддержанные move, style и edit_text можно выполнять на месте по точным ID. Изменение SVG-градиента, прозрачности, состава ошибочной вставки или порядка слоёв требует пересборки:
- после каждого принятого этапа вызывай corel_save_document с НОВЫМ путём `WORKDIR\work\stage_NN_vN.cdr`; фиксируй job.result.document, path, bytes и снимок структуры;
- при подтверждённо завершённой операции: corel_close_document `{request_id,document_id,discard_changes:true}` → corel_open_document `{request_id,path:последний_принятый_stage}`; если исход операции неизвестен, автоматического отката нет;
- после reopen заново получи document_id, page_id, layer_id и все static_id через полную inspect; прежние opaque IDs, StaticID и revision не считать переносимыми. Сверь геометрию/текст с сохранённым снимком и восстанови семантическую таблицу; неоднозначность mapping — BLOCKED;
- все пробы — ТОЛЬКО в собственном черновом документе corel_create_document. Закрой только его точный document_id с discard_changes=true после окончания jobs. Ошибочную структуру слоёв в основном документе проще исправлять новым собственным документом/пересборкой, а не фиктивным reorder.

static_ids — уникальные положительные целые, максимум 100 на обычный вызов. Рисование возвращает `job.result:{document_id,partial,affected_static_ids,created_static_ids,deleted_static_ids,items,...}`. В items: static_id, type, layer_id, bounds_mm `{left,bottom,width,height}`, rotation_deg, fill_type, outline_type, outline_width_mm; uniform fill/outline могут иметь color. После группировки перечитай реальные ID: старые корни/родители меняются. Для batch отдельно прочти его inputSchema — это не массив произвольных вызовов.

Документы: create `{request_id,width_mm:200,height_mm:124.4}`, open `{request_id,path}`, save `{request_id,document_id,path}`, close `{request_id,document_id,discard_changes:true}`. Create/open возвращают DocumentInfo непосредственно в job.result (document_id,name,path,dirty,pages,active_page,unit,preserve_selection); save — `{document:DocumentInfo,path,bytes}`. Status `{}` → job.result с version, documents, active_document_id, executor и capabilities; не угадывай отсутствующий список шрифтов.

Inspect: `{document_id,page_index,recursive:true,max_depth:32,max_visited:50000,limit:500,offset:0,include_text:true}` (без request_id). Прочитай все next_offset; depth_truncated/visited_truncated/pages_truncated/layers_truncated требуют устранения неполноты или отчёта BLOCKED. static_ids-фильтр включает только совпавшие фигуры: ID группы не выбирает автоматически её потомков. Для полной векторной проверки не фильтруй по корням. Результат: document, pages `{index,page_id,width,height}`, page_index/page_id, layers, shapes, total_shapes, next_offset и флаги усечения. В shapes — static_id,type,layer (имя),parent_static_id,depth,bounds_mm,appearance,effects. `layers[].shapes` и total_shapes считают верхний уровень, не все дочерние фигуры.

Guide: `{topic,offset:0,limit:20000}` → немедленно `{topic,text,total_characters,next_offset}`, без темы — topics. Describe API: `{kind:"enum",name:имя_перечисления_из_метаданных,filter:"",offset:0,limit:200}` → job с items/next_offset; для kind="types" name не обязателен. Не выдумывай имена перечислений: при необходимости сначала прочитай types, затем enum/members; сведения SDK не расширяют tools/list.

# 2. ЕДИНИЦЫ И КООРДИНАТЫ

- Страница документа: 200 × 124,4 мм. 1 px референса = 0,1 мм.
- API принимает мм, начало — левый нижний угол страницы, ось Y вверх (так сказано в документации сервера).
- Перевод: x_мм = x_px / 10;  y_мм = (1244 − y_px) / 10;  размер_мм = размер_px / 10. Пример: центр кнопки Y (1577; 350) → (157,7; 89,4) мм.
- Для bbox `(xmin,ymin,xmax,ymax)` в px: lower-left API `(xmin/10,(1244−ymax)/10)`, ширина `(xmax−xmin)/10`, высота `(ymax−ymin)/10`. Эллипс тоже задаётся bbox, не центром/радиусом. Сдвиг из px: dx_mm=dx_px/10, dy_mm=−dy_px/10.
- Внимание: `items[].bounds_mm` рисования и import_bounds_mm нормализованы к странице; `inspect.shapes[].bounds_mm` в текущем worker переводит native координаты в мм, но НЕ вычитает начало страницы. `pages[].width/height` — единицы document.unit, не универсально мм. В КТ-0a измерь offset inspect относительно известной фигуры. В основном документе используй собственный BG-прямоугольник в `(0,0)` как проверенный origin-anchor: его inspect left/bottom — вычитаемый offset; держи его ID. Проверяй offset после reopen. Если нормализация не подтверждена, не делай ложных геометрических выводов.
- Все координаты в разделах 5–6 даны в px референса (начало слева сверху, Y вниз) и являются ПРИБЛИЗИТЕЛЬНЫМИ. Если измерение референса (раздел 4) расходится с ними больше чем на 5 px, прав измерение.
- В SVG-файлах единицы пользователя = px референса (абсолютные координаты, Y вниз). Это единственное место, где Y вниз.

# 3. СТРАТЕГИЯ: НАТИВНЫЙ КАРКАС + SVG-ВСТАВКИ

## 3.1. Что делается нативно
Документ и слои, белый фон (corel_create_shapes: rectangle x_mm=0,y_mm=0,width_mm=200,height_mm=124.4 → corel_style_shapes uniform RGB 255/255/255 и outline none), текст (corel_create_text → corel_edit_text format при необходимости → corel_style_shapes), перемещение corel_transform_shapes/action="move", группировка corel_group_shapes, сохранение и экспорт. Создавай/оформляй фигуры в проверенном порядке перекрытия: отдельного bring-to-front нет.

## 3.2. Что делается SVG
Детали с градиентами и мягкими переходами, если КТ-0b пройдена. Один или несколько версионированных SVG на этап/слой/логическую деталь; отдельные файлы куполов и бликов S7. Генерируй на хосте скриптом `work\gen_SN.py` из измеренных параметров; координаты округляй до 0,1 px. Для 200 точек текстуры на колпачок проверяй лимит импортируемых корней: нейтральный `<g>` может объединить их, но фактическую структуру подтверждает импорт. При необходимости разделяй на файлы с ≤100 фигурами; не полагайся на автоматическую группировку фильтра.

Импорт: corel_import с точными document_id/page_index/layer_id, request_id, format="svg", абсолютным локальным path, size_bytes и SHA-256 (64 символа lowercase hex). Хост вычисляет fingerprint по конечным байтам файла, например Python hashlib; после вычисления файл не менять. Лимит 256 МиБ, без сетевых путей, symlink/reparse/junction; фактически 1–100 корневых объектов, глубина обхода ≤32, ≤50000 фигур. При отказе не обходи фильтр через clipboard/диалог. Обязательные x_mm/y_mm задают нижний левый угол фактического общего bbox импорта, НЕ исходный offset viewBox.

Для SVG bbox `(X,Y,W,H)` в координатах референса импортируй без fit в `x_mm=X/10,y_mm=(1244−Y−H)/10`; root width/height в мм задают финальный масштаб. Сервер переносит импорт так, чтобы его измеренный geometry bbox (без outline) оказался в этой точке. Отдельно проверь native bbox: невидимые фигуры/границы градиента/особенности фильтра могут изменить измерение.

## 3.3. Консервативное подмножество SVG для ЭТОГО генератора

Это наша политика предсказуемой векторной подготовки, НЕ whitelist сервера и НЕ гарантия fidelity. Реальный валидатор запрещает DTD/processing instructions, активное содержимое (script, foreignObject, animate*, set, discard), события on*, непустой xml:base, внешние resource references, CSS escapes и at-rules. Сам по себе он не запрещает filter/clipPath/mask/transform/text/style и не ограничивает команды path/число stop; такие конструкции здесь не используем из-за риска изменения оформления/растеризации. Сервер допускает embedded PNG/JPEG data URI, но в ЭТОЙ задаче они запрещены наряду с любыми image.

- Элементы: svg, defs, g (без атрибутов оформления), path, circle, ellipse, rect, linearGradient, radialGradient, stop.
- path: только абсолютные команды M, L, C, Z.
- Явные fill и stroke у каждой фигуры; без обводки stroke="none". Используемая обводка — только сплошной цвет, 1–2 px (stroke-width); градиентных обводок не создаём.
- Градиенты: gradientUnits="userSpaceOnUse", до 8 stop; ссылки url(#id) только на градиенты из того же файла.
- Прозрачность: только stop-opacity внутри stop и fill-opacity у отдельных фигур. НИКОГДА opacity на g: валидатор может пропустить, но native эффект на самой группе блокирует последующие операции.
- Не генерировать: filter, mask, clipPath, pattern, image, text, use, style/CSS, transform, foreignObject, script, внешние ссылки, DOCTYPE/ENTITY, события. Мягкое затухание — через градиенты на векторных фигурах; это имитация, не Gaussian blur. Текст создаётся нативно.
- Корень с ВЫЧИСЛЕННЫМИ числами: например `<svg xmlns="http://www.w3.org/2000/svg" viewBox="1000 400 300 200" width="30mm" height="20mm">`. Не записывай выражение W/10 в атрибут. viewBox равен geometry bbox всех фигур (px); ширина/высота — его размеры /10 мм.
- Вычисляй geometry bbox скриптом `work\svgbbox.py` без внешних пакетов: для cubic предпочтительно аналитические экстремумы производной (64-точечная выборка — только приближённая контрольная оценка), circle/ellipse/rect — аналитически. Stroke bounds учитывай отдельно, defs/gradient не считать фигурами. Невидимые фигуры могут влиять на native bbox; не добавляй фиктивные невидимые рамки для позиционирования.

## 3.4. Ограничения объектов после импорта
Для поддержанных фигур с локальной прозрачностью допускаются corel_transform_shapes move/rotate, corel_group_shapes group/ungroup, corel_manage_layers move_shapes, а также corel_duplicate_shapes/corel_grid_duplicate. Условия: ровно один cdrLens; transparency uniform/fountain, не frozen; lens не frozen и без uses_viewpoint; у самой группы нет эффектов, все потомки проходят проверку. Просто наличие cdrLens НЕ означает допуск. К таким фигурам не применяй scale, flip, align, shelf-layout, boolean, convert, style. Поэтому:
- SVG готовится сразу в финальном размере; размещение корректируется только сдвигом (move);
- не группируй фигуры внутри SVG с эффектами на уровне группы;
- при UNSUPPORTED_SHAPE используй static_id из сообщения/отчёта и effects в полной inspect. Если неполнота effects.complete=false или appearance=null не позволяет доказать допустимость — REWORK/BLOCKED, не обход. Структуру/эффекты исправляй пересборкой из принятого checkpoint.

## 3.5. Протокол размещения после импорта
1. Дождись фактического завершения job по 1.1. Прочти job.result.imported_root_static_ids, created_static_ids, items, import_bounds_mm и import_diagnostics. Последний содержит source_fidelity/font_fidelity/effect_fidelity (unknown), inspection_status, text_shape_count, observed_fonts, observed_effect_count, unsupported_shape_types и warnings. Пустой список unsupported_shape_types не доказывает отсутствие растра.
2. Сделай полную recursive inspect без фильтра только по корням; собери всех потомков по parent_static_id, дочитай пагинацию. Сопоставь новые ID со структурой до импорта, учитывая created_static_ids и imported_root_static_ids. Требуй import_diagnostics.inspection_status="passed"; unknown означает неполноту, в том числе возможный скрытый PowerClip. Inspect обходит группы, но НЕ содержимое PowerClip и не публикует отдельный признак его наличия. Сам PowerClip в этом workflow не создавать; неподтверждённое скрытое содержимое — REWORK/BLOCKED, не PASS по отсутствию видимых bitmap.
3. У всех новых фигур проверь type (bitmap — 5 в текущем контракте; при другой версии уточни enum), appearance.fill_type и effects. Принимай только подтверждённые векторные fill: none/uniform/fountain, расшифрованные по enum установленного API; bitmap/pattern/texture/PostScript и любое непроверенное представление — REWORK/BLOCKED даже без отдельной bitmap-фигуры. Инспекция видит тип заливки/uniform color, список максимум 32 effects и часть параметров прозрачности, но не читает содержимое сложных заливок, gradient stops/геометрию градиента и не подтверждает полную fidelity. Векторность требует одновременно отсутствия bitmap в доступном полном дереве, допустимых fill/effects и отсутствия неподтверждённого скрытого содержимого; правильность градиента/затухания — дополнительно preview и КТ-0b. appearance=null/effects.complete=false не считать доказательством. Те же правила применять к каждому этапу и итоговой инспекции, не только к тестовому SVG.
4. Сравни размер import_bounds_mm и нормализованные bounds с bbox генератора (×10 в px). Сдвиг исправляй move, размерный/структурный дефект — пересборкой: move не меняет размер. Допуск 3 px для размещения SVG; повтори inspect.
5. Если импорт уже один root-group, повторно не группируй его с самим собой. Если ≥2 подходящих roots одного слоя и родителя, сгруппируй corel_group_shapes; один root оставь как есть. Запомни новый group ID и проверь дерево/эффекты после операции. Группы разных деталей не смешивать между слоями.

## 3.6. Запасной вариант (включается только по результату КТ-0b)
Если КТ-0b покажет проблему только прозрачности, допускается отдельный проверенный вариант: непрозрачные SVG-градиенты плюс непрозрачные фигуры заранее смешанных цветов для бликов/теней. Если и обычные градиенты не подтверждены, используй только сплошные заливки:
Перед основным документом проверь выбранную альтернативу отдельной пробой в черновике (create/import → inspect → preview → save/reopen → свежая inspect), не считай её принятой лишь потому, что прежний вариант провалился. Если нужно разделить файл из-за лимита корней, проверь размещение/порядок нескольких вставок тем же способом.
- градиент = 12–40 вложенных непрозрачных фигур с плавно меняющимся цветом (кольца для кругов, полосы для плоских деталей);
- мягкая тень/блик = 6–10 концентрических фигур, цвет которых заранее смешан с цветом подложки (прозрачности нет);
- контуры — corel_create_curve (явные cubic-сегменты), массовые фигуры — corel_create_shapes (до 100 за вызов) + corel_style_shapes; только при уже включённом hybrid — corel_create_batch/corel_update_batch по их схемам (до 1000);
- дублирование — corel_duplicate_shapes; corel_grid_duplicate только для подходящих сеточных деталей (исходники перемещаются в первую ячейку), не для произвольной фактуры.
Премикс считается относительно локальной подложки; на неоднородном корпусе один premixed цвет не воспроизводит настоящую прозрачность. Все блики/тени S1–S9 в этом режиме заменяй цветными непрозрачными фигурами, не оставляй fill-opacity/stop-opacity. Фотореализм может не достигнуть порога: не понижай критерии автоматически, фиксируй NOT_ACCEPTED при их провале.

## 3.7. Текст
corel_create_text с kind="artistic", явным установленным font_family и font_size_pt. Не называй начертание семейством: `font_family:"Arial"` плюс corel_edit_text/action="format",bold=true, а не угадываемое `"Arial Bold"`. В черновике проверь доступность и readback; публичного перечислителя установленных шрифтов нет.
- BACK / START / MODE: кандидаты Bahnschrift, Eurostile, Arial Black, Verdana; использовать только реально принятое точное семейство.
- «Logitech» и ABXY: кандидаты Century Gothic, Nunito Sans, Segoe UI, Arial; bold задаётся отдельно, точность Semibold через этот API не обещать.
- FONT_NOT_INSTALLED обычно предвалидационный, но FONT_SUBSTITUTED может возникнуть ПОСЛЕ создания. Перед следующим кандидатом проверь error.applied/result.partial/created_static_ids; пробуй на чистом черновом checkpoint, не накапливай ошибочный текст в рисунке. Не разрешай тихую подмену.
- Tracking/kerning недоступны. Для BACK/START/MODE допустима имитация: отдельная artistic-фигура на букву, измеренная ширина и явные интервалы/сдвиги, затем группа; это приближение, не значение «tracking +120» в аргументах.
- Только BMP без NUL/суррогатов. Цвет — corel_style_shapes. Высоты заглавных ≈22 px, ABXY ≈46 px, «Logitech» ≈28 px — цели readback, не прямое значение font_size_pt. Начальный размер в pt оценивай из мм, затем корректируй corel_edit_text format по фактическому bbox и центрируй move. X/y создания не трактуй как центр. Для неподдержанного/неподходящего шрифта возможна векторная отрисовка букв кривыми без font substitution, но типографическое совпадение при этом отдельно оценивать.

## 8.9. compare.py (сохрани как WORKDIR\work\compare.py; нужны Pillow и numpy)

На этапе считай IoU только для уже готового силуэта/зоны; полный IoU S1+S2 проверяй после S2. Для численной проверки оба изображения приводятся к сетке референса ТОЛЬКО после контроля правильной рамки/пропорций; точный размер выпуска отдельно проверяется до resize. Открой коллаж и опиши видимые расхождения. Если изображения открыть нельзя, запиши неполноту контроля: метрики/inspect не подтверждают материал и фотореализм, финальный PASS по всем критериям невозможен.

```python
import os
import sys
import numpy as np
from PIL import Image

HERE = os.path.dirname(os.path.abspath(__file__))
REF = os.path.join(HERE, "..", "ref", "orig.jpg")

def load(path):
    ref = Image.open(REF).convert("RGB")
    shot = Image.open(path).convert("RGB")
    if ref.size != (2000, 1244):
        raise ValueError(f"Размер референса не 2000×1244: {ref.size}")
    print("Размер файла до нормализации:", shot.size)
    if abs(shot.width / shot.height - ref.width / ref.height) > 0.005:
        raise ValueError(f"Пропорции снимка не совпадают с референсом: {shot.size}")
    return ref, shot.resize(ref.size, Image.LANCZOS)

def compare(shot_path, prefix, box=(0, 0, 2000, 1244)):
    ref, shot = load(shot_path)
    r, s = ref.crop(box), shot.crop(box)
    a, b = np.asarray(r).astype(int), np.asarray(s).astype(int)
    diff = np.abs(a - b).sum(axis=2)
    heat = Image.fromarray(np.clip(diff / 300 * 255, 0, 255).astype(np.uint8)).convert("RGB")
    mix = Image.blend(r, s, 0.5)
    sil_a, sil_b = a.min(axis=2) < 240, b.min(axis=2) < 240
    iou = (sil_a & sil_b).sum() / max((sil_a | sil_b).sum(), 1)
    w = 700
    k = w / r.width
    tiles = [im.resize((w, max(1, int(im.height * k)))) for im in (r, s, heat, mix)]
    h = tiles[0].height
    sheet = Image.new("RGB", (w * 2 + 10, h * 2 + 10), "white")
    for i, t in enumerate(tiles):
        sheet.paste(t, ((i % 2) * (w + 10), (i // 2) * (h + 10)))
    sheet.save(prefix + "_cmp.png")
    print(f"IoU силуэта: {iou:.3f} | средняя абс. ошибка: {np.abs(a - b).mean():.1f}/255")

    return tuple(int(v) for v in px.mean(axis=0))
```

## 8.10. Типичные ловушки
- Проба сделана в основном документе: убрать её нельзя. Пробы только в черновом.

- Нарушение политики генератора (filter, clipPath, opacity на g, text, transform, любые image); её нельзя выдавать за точный whitelist сервера.

- Повтор мутации после timed_out/unknown/failed с partial=true или applied=true/неизвестно; partial ошибочно принят за status.
- Превью/inspect отправлены до реального окончания job, либо объявлен PASS при cleanup failure.
- Путаница систем координат: в SVG Y вниз в px, в API Y вверх в мм.
- Центр передан вместо lower-left; viewBox offset принят за положение импорта; inspect origin-offset не учтён.
- В PNG переданы color_mode/transparent/pixel_width; размер файла объявлен точным без чтения PNG.
- Придуманы tracking/reorder/delete; неполное дерево или пустой unsupported_shape_types объявлены доказательством векторности.
- После reopen повторно использованы старые page/layer IDs, StaticID или revision без новой инспекции.
