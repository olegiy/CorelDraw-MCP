# Подтверждение распространения interop

Статус на 12 ноября 2026: право распространять `VGCore.Interop.dll` **не подтверждено**.
Пользователь выбрал распространяемый готовый пакет с предварительным подтверждением прав.
Это условие блокирует публикацию/упаковку готового релиза; локальная development-сборка
и её тесты не являются поставкой и не заменяют этот gate.

Сборка генерируется на build-машине из установленной официальной VGCore 27 type library.
Никакая Corel DLL из стороннего источника не загружается. Нативный CorelDRAW, установщик,
type library и vendor interop в проект не копируются для распространения.
Идентичность исходной type library зафиксирована в `api-contract.json`:

- GUID `95e23c91-bc5a-49f3-8cd1-1fc515597048`, версия 27.2, SYS_WIN64.
- SHA-256 `7044b6074dfa445f39f6238062ae40e96e01c7764dc28d215872abacce3bdd7c`.
- Целевой CorelDRAW 27.2.0.135; C# `net10.0-windows`, x64, встроенный RCW interop.

Проверены официальные [страница SDK](https://community.coreldraw.com/sdk),
[EULA](https://www.corel.com/en/eula/),
[Specific Terms](https://www.corel.com/en/eula/licensing-terms/) и
[Corel Copyrights, Use of Software](https://www.corel.com/en/corel-copyrights/).
Страница SDK подтверждает возможность разрабатывать расширения, но найденный текст
не задаёт явных условий повторного распространения именно генерируемой interop-сборки.
На странице Copyrights Corel предлагает определять права распространения по лицензии
и обращаться за отдельным разрешением при необходимости. В установленном дереве
обнаружен HTML-шаблон окна EULA; отдельная лицензия SDK/redistributable manifest не найдена.

Повторный поиск 12 ноября не выявил явного grant. Официальная статья
[об управлении CorelDRAW из внешних процессов](https://community.coreldraw.com/sdk/w/articles/217/controlling-coreldraw-or-corel-designer-applications-from-other-processes)
описывает ссылку на установленную interop-сборку, но не подтверждает условия её включения
в независимый распространяемый пакет. Условия поставки сторонних проектов не используются
как разрешение от правообладателя.

Это запись о незакрытом условии поставки, а не заключение о том, что распространение запрещено.
Не заменять подтверждение фактом доступности SDK, сторонним GitHub-пакетом, отсутствием
технического ограничения или разрешением пользователя установить приложение.

Для закрытия gate нужен применимый текст лицензии/письменное разрешение Corel,
которое однозначно покрывает данный артефакт и способ поставки. Сохранить источник,
дату и точную редакцию; затем зафиксировать принятое основание и ограничения в отчёте.
Готовый релиз не публиковать до этой проверки.

## Проект запроса в Corel

Адресат: `permissions@corel.com`, указанный на официальной странице
[Permissions Department](https://www.corel.com/en/permissions/).
Тема: «Условия распространения generated VGCore interop для CorelDRAW 27».
Для отправки нужно указать контактные данные заявителя; они в проект не подставлялись.

Просим подтвердить условия распространения генерируемой interop-сборки для независимого
Windows-приложения автоматизации CorelDRAW 27. Сборка создаётся из официально установленной
VGCore type library штатным .NET TypeLibConverter на build-машине. Приложение использует
типизированный COM Interop и требует отдельную лицензированную установку CorelDRAW у получателя.
Сам CorelDRAW, его установщик и нативные библиотеки в пакет не включаются.

1. Разрешено ли включить такую генерируемую `VGCore.Interop.dll` в распространяемый пакет
   вместе с self-contained приложением .NET 10 для Windows x64?
2. Какие лицензия, уведомления, ограничения версии и иные условия применяются?
3. Если такой вариант не разрешён, предусмотрен ли официальный redistributable interop
   или другой разрешённый способ поставки готового приложения без SDK на машине получателя?

Запрос подготовлен для проверки пользователем и никуда не отправлен.
