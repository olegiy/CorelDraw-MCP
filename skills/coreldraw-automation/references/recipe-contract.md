# Контракт VBA-рецепта

Рецепт — это обычный стандартный UTF-8 модуль VBA, который запускается через
`corel_execute_vba`. Это не отдельный MCP-инструмент и не новый исполнитель.
Сервер сам создаёт временный GMS, одну внешнюю Undo-группу и выполняет
`Public Function Main() As String` в точном документе из аргумента
`document_id`.

## Вход и результат

- Перед каждым вызовом сначала получите актуальный `document_id` через
  `corel_status` или `corel_inspect_document`.
- Рецепт обязан иметь `Main() As String` и вернуть валидный JSON даже при
  отсутствии изменённых объектов. Успешный результат должен описывать
  фактически применённое действие и возвращённые `StaticID`.
- Ошибку проверки предусловий или ошибку действия нужно передавать через
  `Err.Raise`; нельзя возвращать успешный JSON после подавления ошибки.
- Для локали используйте `JsonNumber`, `JsonEscape` и `JsonString` из
  `M_CommonHelpers.bas`: десятичный разделитель всегда `.`, управляющие
  символы и кавычки экранируются JSON-правилом.

Пример результата:

```json
{"ok":true,"action":"duplicate","source_static_id":123,"result_static_id":456}
```

Для результата, который рецепт хочет передать как диагностическую ошибку,
используйте `RecipeError(code, message, applied)`. Это строка JSON для
описания результата; она не заменяет `Err.Raise`, если операция должна быть
неуспешной.

Шесть адресных рецептов передают ошибки через `Err.Source="CorelMcpRecipe"`
и JSON-описание из `RecipeFailure`. Worker сохраняет в `job.error.applied`
консервативный флаг: false означает отказ до первого изменяющего вызова,
true означает, что действие уже могло примениться (не доказательство полного
успеха). Коды: `RECIPE_VALIDATION_FAILED` и `RECIPE_ACTION_FAILED`.
Сбой восстановления выделения добавляется в `cleanup.errors` с шагом
`recipe.selection` и `cleanup.completed=false`. Для произвольного VBA такой
флаг недоступен: `VBA_RUNTIME_ERROR` сам по себе не доказывает отсутствие изменений.

## Цели и границы

Фигура выбирается только по точному `StaticID` внутри текущего документа и
страницы. Нельзя использовать порядковый индекс как замену идентичности,
активный документ как неявную цель или искать «похожую» фигуру после
ошибки. `StaticID` действителен только пока живут конкретная фигура и
документ; после переподключения ID документа нужно получить заново.
Harness получает точный COM Document, активирует и проверяет его перед Main.
Если после Main активен другой документ, возвращается TARGET_DOCUMENT_CHANGED.
Это обнаружение, а не изоляция: произвольный VBA может сам обратиться к любому
документу, в том числе переключиться и вернуться. Запрещайте такие действия
в рецептах; `document_id` не является sandbox.

Общие функции ограничивают глубину и число посещённых фигур. Пустое
выделение, отсутствующий `StaticID`, заблокированный слой и неподдерживаемый
тип должны завершаться явной ошибкой до изменения или честным описанием
частичного действия. Рецепты не обещают транзакционный откат произвольного
VBA.

Сервер восстанавливает настройки документа, активный документ и завершает
свою Undo-группу независимо по шагам. Он не обещает восстановление произвольного
изменённого кодом выделения/страницы или отмену действия. Рецепты явно сохраняют
и восстанавливают собственный контекст; ошибки этого восстановления не являются
успехом. Рецепт не должен
вызывать `SaveSettings`, `RestoreSettings`, `BeginCommandGroup` или
`EndCommandGroup`; его собственные изменения геометрии и внешних файлов не
откатываются автоматически.

Не используйте `Eval`, `Execute`, shell, диалоги, `Application.Quit`,
произвольный доступ к файлам или установленные GMS. Перед публикацией новый
рецепт проверяется на временном документе CorelDRAW 27 и документируется в
`references/recipes.md` с предусловиями, измеряемыми полями результата и
ограничениями.
