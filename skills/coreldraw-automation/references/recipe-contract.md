# Контракт JSON-рецепта

Рецепт — проверяемая последовательность готовых MCP-вызовов, не исполняемый код. Каждый файл examples/*.json содержит schema_version, title, preconditions, steps, postchecks и limitations. Каждый step имеет tool и arguments, соответствующие действующей строгой схеме. Произвольные выражения, Eval/Execute, шаблоны исходного кода и универсальные COM-вызовы отсутствуют.

Перед запуском прочитайте предусловия. Замените строки <document_id>/<layer_id>/<page_id> точными ID текущего сеанса. Числа StaticID 1001/1002 — структурные примеры: используйте реальные ID из inspect/create. Нулевые revision и SHA-256 не являются разрешением на применение и заменяются наблюдаемым значением. Пути и размер входного файла также должны быть фактическими.

Каждый новый изменяющий step получает новый request_id. Принятый Job читается через corel_get_job; повтор с тем же request_id не создаёт ещё одну мутацию. В JSON используются конечные числа с обычной JSON-точкой независимо от locale. Пользовательский текст и пути не передаются через shell.

После каждого изменяющего шага проверяйте фактические IDs/параметры, error.applied, cleanup.completed и затем inspect/preview. Если результат partial/unknown/timed_out или cleanup не завершён, следующие мутации не запускаются автоматически. Не переписывайте исходный отчёт и не подставляйте выдуманный revision.
