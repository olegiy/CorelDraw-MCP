# Тестовый запуск VBA через MCP

Этот этап добавляет фиксированную процедуру `duplicate_demo`. C#-воркер передаёт ей точную фигуру и целое число копий. Макрос размещает копии вправо с зазором 5 мм между абрисами и возвращает StaticID. Воркер сверяет их со страницей и записывает результат в `corel_get_job`.

## Подготовка на тестовой машине

1. Соберите имеющийся в репозитории `CorelMcp.NativeBuilder` и воркер на SDK 10.0.404 с заданным CorelDRAW 27 interop.
2. В интерактивной сессии Windows выполните из корня проекта команду `dotnet run --project tools/CorelMcp.NativeBuilder -- --developer-prepare-duplicate-demo .`. Утилита создаёт отдельный `artifacts/duplicate-demo/CorelMcp.DuplicateDemo.gms`. Рабочий GMS обрабатывается собственными командами сборщика.
3. В редакторе VBA выберите `CorelMcp_DuplicateDemo`, выполните **Debug → Compile** и сохраните GMS. Выгрузите этот тестовый GMS из CorelDRAW. Снимите SHA-256 с сохранённого файла и укажите его при запуске тестового MCP-клиента.

| Параметр окружения | Значение |
| --- | --- |
| `CORELDRAW_MCP_CSHARP_WORKER` | Абсолютный путь к собранному тестовому C#-воркеру. |
| `CORELDRAW_MCP_DUPLICATE_DEMO_GMS` | Абсолютный путь к сохранённому доверенному тестовому GMS. |
| `CORELDRAW_MCP_DUPLICATE_DEMO_SHA256` | SHA-256 этого GMS в шестнадцатеричном формате. |

Запустите тестовый сервер отдельной регистрацией stdio через `node dist/index.js`. Первым вызовите `corel_list_macros` и проверьте флаг `configured`. Команды относятся к прямому MCP-подключению. Политика панели пока их не выдаёт. Разрешённый запуск относится только к GMS, который оператор указал локально. VBA выполняется с правами CorelDRAW, поэтому перед настройкой проверяйте происхождение исходников и GMS.

## Вызов и проверка

Создайте временный документ, добавьте одну фигуру и возьмите точные идентификаторы из инспекции. Вызовите `corel_run_macro` с `macro_id: "duplicate_demo"`, номером страницы, массивом `static_ids` из одного элемента, `parameters: {"count": 3}` и новым `request_id`. Готовый отчёт содержит `macro_version` (SHA-256), `requested_copies`, `vba_status` и `created_static_ids`. После успеха на странице должны быть четыре фигуры.

| Ситуация | Диагностика |
| --- | --- |
| Неверное имя макроса, число копий или набор StaticID | Строгая проверка схемы до вызова VBA. |
| Файл отсутствует или хеш отличается | `MACRO_ARTIFACT_INVALID` без изменения рисунка. |
| Проект с тем же именем уже загружен | `MACRO_ALREADY_LOADED`. Выгрузите проверенный тестовый проект перед новым вызовом. |
| VBA вернул обработанную ошибку | `MACRO_RUNTIME_ERROR`, номер ошибки и подтверждённые изменения в отчёте. |
| Результат VBA расходится с составом страницы | `NATIVE_OUTCOME_UNKNOWN`. Новые мутации блокируются до проверки, исходное задание не повторяется. |

Для изолированного живого теста с готовым GMS используйте `CORELDRAW_WORKER_LIVE=1` и команду `node test/integration-macro.mjs`. Тест создаёт два временных рисунка, проверяет копии, повтор с тем же `request_id` и состояние контрольного рисунка. При неизвестном исходе он оставляет состояние доступным для проверки оператором.
