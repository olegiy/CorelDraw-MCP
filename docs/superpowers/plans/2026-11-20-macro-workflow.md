# Подготовка и проверка пользовательских макросов CorelDRAW

> **Для исполнителя:** ведите задачи по чек-листу. Для реализации используйте `executing-plans` или `subagent-driven-development`; живые шаги с CorelDRAW выполняйте последовательно.

**Цель:** по описанию операции подготовить макрос, проверить именно поставляемый `.gms` на временных рисунках и передать его с исходником и короткой инструкцией для самостоятельного запуска.

**Подход:** первый выпуск проверяем на ручном макросе дублирования. Пользовательская точка входа запускается из панели «Макросы»; MCP готовит тестовые рисунки и измеряет результат, но не исполняет пользовательский VBA. Подготовка GMS остаётся отдельным шагом в редакторе VBA.

**Среда:** интерактивный Windows x64, CorelDRAW 27 с VBA; эталонная проверенная версия для MCP-теста: `27.2.0.135`. Для имеющегося тестового контура: Node.js 24 и .NET SDK `10.0.404`.

**Основание:** пользовательский сценарий «описать задачу → получить проверенный макрос и краткий отчёт → запустить из CorelDRAW»; [порядок проверки зарегистрированного макроса](../../duplicate-demo.md); [смежный план VBA/C#](2026-11-20-vba-mcp-csharp.md).

## Что уже доказано

Сохранённый протокол `artifacts/integration-macro/71636655-60b0-4d2f-8f16-e93eb608a9db/verification.json` подтверждает сквозной вызов `M_DuplicateDemo.RunRegistered`: три копии, четыре фигуры на странице, `vba_status: ok`. `test/integration-macro.mjs` также проверяет идемпотентность по `request_id`, восстановление выделения и неизменность контрольного рисунка. Это проверка зарегистрированной процедуры, а не `M_McpDuplicateDemo.DuplicateSelectedObject` из панели «Макросы». `CorelMcp.NativeBuilder --developer-prepare-duplicate-demo` импортирует только `M_DuplicateDemo.bas`, не ручной модуль.

Из рассмотренных вариантов берём ручной запуск отдельного GMS и независимую проверку через MCP: это проверяет тот же интерфейс, которым будет пользоваться оператор. Регистрация каждого нового макроса в MCP потребовала бы менять и сопровождать контракт сервера, а один тест скрытого входа не проверил бы панель и диалоги. Универсального запуска VBA через MCP, автоматической обработки диалогов и изменений пользовательских настроек в этом этапе нет.

## Границы и файлы

- `tools/duplicate-demo/manual/M_McpDuplicateDemo.bas` — исходник пилота. Зарегистрированный `tools/duplicate-demo/M_DuplicateDemo.bas`, `src/tools.ts` и рабочий C#-воркер в рамках пилота не меняются.
- `docs/duplicate-demo.md` — после живой приёмки добавить отдельный раздел для ручного режима, не смешивая его с `corel_run_macro`.
- `artifacts/macro-workflow/duplicate-demo/<run-id>/` — отдельный локальный каталог каждой сборки: пользовательский `CorelMcp.UserDuplicateDemo.gms`, `M_McpDuplicateDemo.bas`, `verification.json` и короткий отчёт. Не перезаписывать уже принятый GMS.
- Не изменять рабочие рисунки, чужие GMS, штатный runtime или регистрацию MCP. Не ослаблять настройки безопасности VBA. Использовать один MCP-владелец за раз; отдельный live-контур допускается только по `docs/test-machine-live-admission.md`.
- Не считать SHA-256 доказательством доверия к исходникам: он связывает проверенные и переданные байты. Код, зависимости и побочные эффекты проверяются отдельно до запуска.

## 1. Подготовить исходник и сборку

- [ ] Записать контракт пилота: `M_McpDuplicateDemo.DuplicateSelectedObject` — публичная процедура без аргументов; требуется ровно один выделенный объект на активной странице; ввод `1–1000` задаёт число **дополнительных** копий; копии идут вправо, зазор между абрисами 5 мм, оригинал остаётся. Отмена, неверное число или выделение не меняют рисунок. Успешная серия образует одну операцию Undo.
- [ ] Проверить существующий ручной модуль по контракту. Убрать не требуемую для поставки запись в `%TEMP%` и автоматический `Undo` в аварийной ветке. Проверять аргументы и пригодность цели до `BeginCommandGroup`. При ошибке закрыть начатую группу, сообщить число подтверждённых копий и явно предупредить о возможной частичной правке; не запускать повтор и не обещать откат.
- [ ] Создать в редакторе VBA собственный локальный проект `CorelMcp_UserDuplicateDemo` в новом каталоге прогона. Импортировать проверенный `.bas`, выполнить **Debug → Compile**, сохранить и выгрузить только этот проект. Если компиляция не подтверждена или проект с таким именем уже загружен, остановиться и установить причину; не трогать чужой проект. Фиксированную команду сборщика для `duplicate_demo` не использовать для ручной версии.
- [ ] Записать SHA-256 исходника и SHA-256 сохранённого GMS (`Get-FileHash -Algorithm SHA256`). Зафиксировать версию CorelDRAW, внутреннее имя проекта и имя точки входа. В следующей задаче загружать этот файл, а не заново импортировать исходник.

## 2. Проверить поставляемый GMS в CorelDRAW

- [ ] Перед отдельным live-прогоном выполнить `node scripts/check-live-admission.mjs --receipt <путь-к-утверждённому-receipt>`. При отказе не запускать тест и не принимать изменившийся снимок автоматически.
- [ ] Создать через MCP два временных рисунка, рабочий и контрольный. На рабочем создать прямоугольник 26 × 18 мм с центрированным абрисом известной ненулевой ширины. Снять исходное состояние обоих через `corel_inspect_document` с точными `document_id`, страницами и StaticID. Обрезанный снимок не использовать для приёмки.
- [ ] Загрузить проверяемый GMS и подтвердить его имя и путь. На временном рабочем рисунке оператор выбирает прямоугольник и запускает `DuplicateSelectedObject` из панели «Макросы» с числом `3`. После подтверждения результата инспекция должна показать ровно четыре верхнеуровневые фигуры, сохранённый StaticID оригинала, три разных новых StaticID, неизменные размеры и положение по Y. Для прямоугольников с одинаковым центрированным абрисом рассчитать каждый видимый зазор по данным `corel_inspect_document`: из разности соседних `bounds_mm.left` вычесть `bounds_mm.width` и `appearance.outline_width_mm`. Ожидается `5 мм` с допуском `0,01 мм`. Контрольный рисунок не меняется.
- [ ] Проверить Undo одним действием на временном рабочем рисунке: три копии исчезают, исходный объект остаётся. Отдельно проверить отмену диалога, ввод `0` и `1001`, пустое выделение и выделение двух объектов (для последнего добавить вторую фигуру и снять отдельный снимок до вызова). После каждой попытки сравнить состав и геометрию с её исходным снимком; изменение выделения самим оператором не считать изменением рисунка.
- [ ] Записать в `verification.json` версию CorelDRAW, оба SHA-256, результаты проверок, IDs заданий MCP и статус очистки. После известного исхода закрыть только рисунки, созданные для теста; выгрузить только тестируемый проект и убедиться, что CorelDRAW отвечает. При `timed_out`, `unknown`, неожиданном диалоге или неподтверждённой очистке сохранить диагностику, не повторять мутацию и не выдавать результат за пройденную приёмку.

## 3. Передать проверенный макрос

- [ ] Сверить SHA-256 файла, предназначенного к передаче, с SHA-256 проверенного GMS и повторно сверить исходник. Любая пересборка или расхождение требует нового прогона, а не обновления хеша в старом отчёте.
- [ ] Передать `.gms`, соответствующий `.bas` и короткий отчёт: что делает макрос, на какой версии проверен, что выделить, как загрузить проект и выбрать `DuplicateSelectedObject` в панели «Макросы», как проверить результат на копии рисунка и как отменить успешное действие. Для запуска пользователю не нужны MCP, Node.js или SDK. Проверенные пункты и ограничения перечислить отдельно.
- [ ] Дополнить `docs/duplicate-demo.md` инструкцией ручного режима. Для следующего макроса сохранить тот же порядок: из постановки выписать цель, допустимые объекты и параметры, ожидаемые изменения и проверяемый пример. Для каждого макроса подготовить свои позитивный и негативный сценарии; проверки дублирования не считать доказательством для другой операции. Решение об автоматизации сборщика принимать отдельно после пилота.

## Критерий готовности

В поставку идёт тот же по SHA-256 GMS, который успешно скомпилирован и запущен из панели на временных рисунках. Геометрия, отказ без мутации, Undo, изоляция контрольного рисунка и очистка подтверждены. Отсутствие живого прогона, коллизия проекта, смена хеша, неполная инспекция или неизвестный исход блокируют статус «проверен». Исторический успех `corel_run_macro` остаётся отдельным результатом.
