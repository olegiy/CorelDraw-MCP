# Гибридный исполнитель CorelDRAW 27: проектное решение

Дата: 13 ноября 2026. Статус: проект для согласования; реализация не начата.

Пользователь выбрал гибридную архитектуру после живых испытаний и попросил сначала план, включая исправление выявленных ошибок. Основание: [отчёт испытаний](../../live-backend-comparison-2026-11-12.md). Полного сравнительного покрытия всех вариантов 47 групп нет.

## Цель и рабочая база

Сохранить строгий MCP и надёжность C#-worker, а массовые операции выполнять фиксированными VBA-процедурами внутри Corel. Устранить создание/компиляцию временного GMS на каждый вызов и повторные межпроцессные обходы объектов.

Рабочая база — существующее дерево `.kilo/worktrees/codex-like-ui-task-1`, где находятся C# 0.3.0 и результаты испытаний. Корневой checkout на момент подготовки имеет ветку `C#-migration`, HEAD `7aced35`, package 0.2.0, без C#-worker. Это разные состояния. Реализацию не начинать в корневом checkout как будто C# там уже есть; не переключать ветки, не переносить весь накопленный diff и не коммитить автоматически. Сначала сохранить манифест состояния рабочего дерева и отделить будущие изменения гибрида от прежней миграции/UI.

## Архитектура

`MCP TypeScript → существующий JobManager → единственный C# STA worker → выбранный до мутации путь C# либо фиксированный VBA runtime → тот же CorelDRAW`.

TypeScript сохраняет jobs, идемпотентность, артефакты и существующую чистую геометрическую математику. C# валидирует контракт, разрешает точные цели, готовит данные, управляет состоянием/блокировкой и проверяет ответ. VBA быстро применяет проверенный пакет и собирает результат внутри процесса Corel. Перенос существующей TypeScript-математики в C# ради языка не нужен.

Сохраняются Node.js 24, .NET SDK 10.0.404, net10.0-windows x64 STA, CorelDRAW 27.2.0.135 и `Local\CorelDrawMcp_v27`. Все COM-вызовы, включая VBA Load/RunMacro, восстановление и освобождение ресурсов, выполняются на STA под этим mutex. Polling читает reports без COM.

Технический backend остаётся `csharp`; это процесс-владелец COM, а не утверждение о языке каждой операции. Добавляются `execution_mode` в status и `versions.execution_engine = csharp|vba`, `versions.route_policy`, `versions.native_module` в job. Подробные длительности фаз — в отдельном `execution.json`, без скрытого изменения результата существующих инструментов.

## Готовый VBA runtime

- Собственные исходники `worker/vba/`, один собранный GMS и manifest: protocol=1, module/source/GMS hashes, Corel major=27, перечень фиксированных операций.
- Проект `CorelMcp_Runtime_v1_<source-hash-prefix>`, точное имя и полный путь из manifest. Не выбирать по похожему имени или первому проекту.
- Runtime загружается через подтверждённый API `GMSProjects.Load(FileName, CopyFile:false, ForAllUsers:false)`. `GMSManager.RunMacro` доступен только приватному адаптеру с константными именами функций.
- Проверка целостности до выполнения кода; удержание совместимого с Load дескриптора, запрещающего подмену файла при проверке/загрузке. Совместимость этого режима — часть первого живого gate.
- Фиксированные функции: `M_Bridge.Handshake`, `M_Bridge.ValidateFonts`, `M_Bridge.Apply`, позднее `M_Geometry.Extract`. Передаются данные и уже проверенные COM-ссылки Document/Page/Layer/ShapeRange; наружу возвращаются только данные/ID.
- В runtime нет VBE, AddFromString, CommandBars Compile, VBA source, пользовательского macro/project selector, произвольного COM dispatch и исполнения shell.
- Сборочный dev-инструмент может использовать VBE только для своего отдельного проекта при подготовке GMS на машине разработчика. Конечный запуск и установка не зависят от доступа к VBE и ручной компиляции.
- Runtime статeless между командами: не хранит Document/ShapeRange и pending payload в глобальных переменных. Загруженный штатный runtime может разделяться несколькими worker, работающими последовательно под mutex. Обычное завершение worker освобождает свои RCW, но не выгружает общий установленный модуль. Диагностические тесты загружают собственный изолированный проект и выгружают только его.
- Отсутствие VBA, запрет макросов, несовместимый модуль или неподтверждённая целостность дают явный отказ до мутации. Настройки доверия/безопасности Corel автоматически не ослабляются.
- **Первый обязательный gate:** загрузка готового GMS, handshake и вызов без UI-компиляции в новом worker, после перезапуска worker и после запуска нового Corel на стенде без посторонних документов. Пока gate не пройден, переключения по умолчанию нет. Ручная компиляция из исследовательского прототипа не считается решением.

## Маршрутизация первой версии

Конфигурация `CORELDRAW_MCP_EXECUTION_MODE=csharp|hybrid` выбирается при запуске worker и фиксируется для его сеанса. До финальной приёмки default=csharp; после прохождения gate — default=hybrid. Смена режима действует для новых запросов нового сеанса и никогда не повторяет старый job. Пользовательские запросы не выбирают backend.

| Операция | Первоначальная политика hybrid |
|---|---|
| Status, inspection, find-text, curve-read, документы/страницы/слои, import/export/preview, bool, PowerClip, preflight, layout | Существующий C#; улучшения по отдельным проверенным задачам |
| Новые create/update batch | VBA; отсутствие runtime — отказ, без перенаправления |
| create_shapes, общий style, move, duplicate | VBA при >=20 элементов/результирующих копий и поддержанной структуре; меньшие наборы — C# |
| replace/format/set text, convert-to-curves | VBA при >=20 целях, все цели — поддержанный текст без эффектов/вложенности; остальные случаи сохраняют C# |
| group/ungroup, scale/rotate/flip существующего инструмента | Пока C#; перевод возможен только после отдельного парного gate |
| measure_shapes | Сначала прежний C# snapshot + TypeScript math; затем фиксированный VBA extractor после отдельного correctness/performance gate |

Порог 20 — консервативная начальная политика по проверенным объёмам, не доказанный универсальный optimum. Путь выбирается по инструменту, параметрам и проверенной структуре **до изменения документа**. У C# нет аварийного перехвата неудачного VBA-вызова. Отказ, таймаут или неизвестный исход не меняют выбранный путь и не запускают другую реализацию.

## Новые строгие пакетные команды

Предлагаемая версия интерфейса — 0.4.0. Существующие инструменты, их лимиты и смыслы сохраняются.

1. `corel_create_batch`: общие `document_id`, `page_index`, `layer_id`, `request_id`; 1–1000 элементов с уникальным `item_key` длиной 1–100 символов. Варианты: rectangle, ellipse, line и artistic text с теми же полями координат/шрифта, что у действующих команд. Поддерживаются none/uniform RGB/CMYK fill/outline и `rotation_deg` вокруг собственного центра после создания и оформления. Для line запрещены поля прямоугольника; для text обязательны явные family/size. Порядок элементов и результата совпадает.
2. `corel_update_batch`: 1–1000 записей с уникальным `static_id`; каждая содержит fill и/или outline и/или одну transform move/rotate/scale/flip с явными параметрами действующего контракта. Порядок: стиль, затем трансформация. Первоначально только отдельные rectangle/ellipse/curve/line/text без group/bitmap/live effects/PowerClip; вся неподдержанная цель отклоняет пакет до мутации.

Для обеих команд: строгие discriminated unions; NaN/Infinity, дубли, non-BMP, lone surrogate и NUL отклоняются. Общий текст пакета <=100000 UTF-16 units, сериализованная полезная нагрузка <=1 МиБ. Предельный JSONL протокола остаётся 4 МиБ. Ответ содержит item_key/StaticID mappings, созданные/затронутые/удалённые ID, фактические поддержанные свойства и partial/error; крупный результат публикуется проверенным artifact через существующий WorkerArtifacts.

Это две предметные операции, не универсальный сценарный язык. Нет произвольного порядка разнотипных команд, ссылок на результаты будущих шагов, исходного VBA, имён классов/макросов и auto-run после ошибки. Отдельные MCP jobs не объединяются скрыто: для 1000 этикеток агент должен использовать batch-рецепт.

## Проверки и исходы

- До BeginCommandGroup проверяется весь пакет: значения, font availability, document/page/layer identity, все StaticID, предки, locked/special layers, типы/effects, ограничения и размер результата. Проверка шрифтов — одна нативная read-only операция по уникальным именам пакета, без постоянного кэша установленных шрифтов.
- Все targets разрешаются один раз на операцию. Нельзя заменять безопасный обход на FindShape из плоского прототипа, теряя проверки предков. Оптимизация допустима только после тестов на вложенность и блокировки.
- Общая командная группа и StateScope остаются под управлением C#. VBA не делает Begin/EndCommandGroup, Undo, Application.Quit и не меняет глобальные настройки.
- Нативный ответ проверяется по job nonce, protocol/module version, operation, ожидаемым ID/count/order. Строки и числа JSON экранируются/форматируются независимо от locale. Некорректный ответ после передачи мутации означает unknown, не applied=false.
- Известная частичная ошибка возвращает подтверждённые ID/результаты и `applied=true` либо неопределённость там, где подтверждения нет. Dirty не сбрасывается ради красивого результата. Нет автоматического Undo/replay.
- При потере канала/таймауте слот остаётся занят до фактического завершения, сохраняются job и native diagnostics. После неизвестного исхода новые мутации блокируются до существующей процедуры сверки. Повторный request_id не вызывает второй native Apply.
- После операции native module не удерживает объекты частного документа. Сохраняется ранее исправленный порядок: импортные/частные RCW освобождаются до закрытия private document.

## Что именно исправляем по результатам тестов

| ID | Наблюдение и классификация | Обязательное действие |
|---|---|---|
| H01 | Три зависания старого временного GMS-адаптера; точная зависшая инструкция не установлена | Не восстанавливать этот адаптер. Готовый модуль, runtime без VBE/Compile, repeated startup/operations gate; сохранить unknown/no replay |
| H02 | C# повторно обходит страницу и собирает дорогие snapshots; это измеренная проблема производительности | Единая подготовка targets, ShapeRange/нативные loops, сбор обязательного результата внутри Corel; отдельные времена resolve/apply/snapshot |
| H03 | Дорогой повторный поиск шрифта и поштучное создание текста | ValidateFonts по уникальным именам пакета, batch text, проверка фактического шрифта; без подстановок и устаревающего кэша |
| H04 | Пустой viewport после успешных Activate/Refresh в показе | Исправить демонстрационный helper и observe-act-verify через agent-desktop; не заставлять обычный MCP-запрос перехватывать фокус |
| H05 | Nonprinting layer дал нулевые layout bounds; причина/дефект Corel ещё не локализованы | Воспроизвести отдельно. Измерять через безопасный private fixture при возможности; иначе явное unsupported с основанием, без изменения Printable исходного слоя и ложного ZERO_SIZE для ненулевой фигуры |
| H06 | Запрошенный texture preset не подтверждён native readback; ошибка исследовательского пути/неопределённость API | До будущего включения texture-инструмента подтвердить selector в private fixture; несовпадение — отказ, без молчаливой замены |
| H07 | SVG экспортировал полноцветные паттерны как `<image>` | Честная диагностика растрирования для подтверждённых случаев; не обещать векторность. Сохранить CDR как векторный оригинал; не подменять формат молча |
| H08 | Corel повреждает non-BMP/emoji; ограничение Corel, защитный контракт уже есть | Сохранить отказ до мутации и закрепить тестами во всех новых batch-путях |
| H09 | В стенде неверно ожидались bounds без outline, точный угол, неизменный external FilePath; ранние assertions неполные | Общие физические единицы, допуски, разделение reference metadata/appearance; полные проверки каждой цели/каждого временного повтора |
| H10 | cdrPAT оказался import-only; сложные эффекты/spot/mesh не покрыты действующим typed API | Явные capability gates; не объявлять эти операции реализованными и не включать их в скорость гибрида |

H06 и mesh/spot/full complex style API не являются исправлением существующей публичной функции — таких инструментов сейчас нет. Первая поставка гибрида не добавляет весь блок сложных заливок. Добавляется gate/корректная диагностика, расширение этих инструментов оформляется отдельно после подтверждения API.

## Приёмка и выпуск

Функциональная приёмка охватывает все элементы пакета, IDs, порядок, координаты, цвета, контуры, текст/шрифты, неизменность исходников и cleanup. Серии 20/100/1000: прогрев +5 быстрых или3 медленных повторов, с чередованием C#/hybrid; каждая команда проверяется полностью вне её timing. Пять минут на новый случай, кооперативная остановка между native-командами, никаких повторов прежнего часового поштучного сценария.

Основные performance gates: медиана полного сценария 1000 цветных плашек hybrid <=30 с и минимум в2 раза быстрее C# на тех же конечных требованиях; создание20 текстов hybrid <=2 с и минимум в3 раза быстрее C#; PNG/inspection C# без регрессии >20% при повторной серии. Это цели приёмки, не уже измеренные показатели новой реализации. Невыполнение gate не скрывается сменой fixture/сокращением проверки.

Отдельно выполняются geometry100, fault injection и длительный smoke:100 фиксированных native операций без утечки проектов/документов, orphaned payload и тихого зависания. Нельзя объявлять production-готовность по одному удачному запуску.

Распространение interop остаётся заблокированным до подтверждения прав. Собственный VBA source/GMS получает notice и hash/сборочную привязку; готовый пакет не публикуется/устанавливается в рамках этого плана без отдельного решения пользователя. Изменения лицензирования проверяются по фактическим материалам, а не объявляются подтверждёнными из-за наличия MIT у исходников проекта.

Источники сигнатур: Context7 `/websites/community_coreldraw_sdk_api_draw`, API27 и локальная typelib; [GMSProjects](https://community.coreldraw.com/sdk/api/draw/27/c/gmsprojects), [GMSManager](https://community.coreldraw.com/sdk/api/draw/27/c/gmsmanager), [Unload](https://community.coreldraw.com/sdk/api/draw/27/m/gmsproject.unload). Вывод о жизненном цикле готового runtime ещё должен подтвердить первый live gate.
