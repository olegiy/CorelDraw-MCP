# Известный сбой CorelDRAW при закрытии документа

Дата фиксации: 20 ноября 2026. Статус: подтверждён падением приложения; воспроизводится недетерминированно. Влияет на CorelDRAW 27.2.0.135 при работе с гибридным режимом MCP (`CORELDRAW_MCP_EXECUTION_MODE=hybrid`).

## При каких условиях возникает

Сбой зафиксирован только в live-прогонах полного интеграционного набора гибридного режима — 13 сценариев, включающих пакетное создание и оформление до 1000 объектов через VBA-модуль, булевы операции, преобразование текста в кривые, импорт SVG и PowerClip.

Факты по условиям, подтверждённые прогонами 20.11.2026:

- Все четыре зафиксированных падения произошли **в момент закрытия документа** (`Document.Close()` через `corel_close_document`) либо в течение нескольких секунд **после закрытия последнего документа**; в последнем случае все MCP-операции уже вернули успешный результат, и падение не видно в отчёте теста.
- Падающий документ в моментальных случаях — пустой контрольный документ, который MCP только создал и прочитал инспекцией; других операций с ним не выполнялось.
- Падение недетерминировано: полный набор при заранее открытом постороннем документе упал в 3 прогонах из 5; без него — 0 из 3. Сокращённые последовательности (пакет 1000 объектов + сохранение + экспорт + закрытия) не упали ни разу в 11 повторах.
- В проверках C#-пути, включая предыдущие live-гейты (`docs/full-live-gate-2026-11-14.md`), это падение не фиксировалось. Режим по умолчанию `csharp` затронут не был.

Причина по дампам аварий (четыре события): нарушение прав доступа `0xC0000005` — чтение адреса `0x20`/`0x21` в `CrlFOM.dll` 27.2.0.135, функция `WRCOutlineList::RemoveInstance` (разбор списка контуров при закрытии документа), на главном STA-потоке CorelDRAW. То есть внутри CorelDRAW разыменовывается нулевой элемент списка контуров. Код C#-закрытия и VBA-пакетный модуль (`worker/vba/M_Batch.bas`) проверены: используются только документированные вызовы API, глобального состояния нет.

## Как проявляется

- CorelDRAW внезапно закрывается; Windows показывает отчёт об ошибке APPCRASH с сбойным модулем `CrlFOM.dll` (журнал «Приложение», события 1000/1001).
- Если закрытие выполнялось через MCP, задание возвращает `COM_ERROR` с `0x80010105 (RPC_E_SERVERFAULT)` на стадии `closing_document`; все последующие вызовы — `0x800706BE`/`0x800706BA` (RPC-сервер недоступен).
- Возможен «тихий» вариант: MCP-задание закрытия возвращает успех, а приложение падает через несколько секунд после закрытия последнего документа.

## Влияние на работу пользователя

- Несохранённые изменения **всех** открытых в момент падения документов теряются — это обычные последствия аварийного завершения приложения. Файлы, сохранённые до падения, во всех наблюдавшихся случаях оставались на диске неповреждёнными.
- Исход MCP-задания, во время которого произошло падение, **неизвестен**: закрытие могло примениться или не примениться. Автоматический повтор такого задания запрещён семантикой исполнителя.
- При реальной эксплуатации документы закрываются редко и, как правило, вручную. Все наблюдавшиеся падения происходили именно в момент закрытия или сразу после него, поэтому риск сосредоточен в этой точке сессии, а не в операциях рисования, оформления или экспорта.

## Что делать, если сбой возник

1. Не повторяйте задание автоматически: сначала установите фактическое состояние — исход закрытия неизвестен.
2. Перезапустите CorelDRAW вручную. Новая MCP-сессия подключится к запущенному приложению и создаст новый worker; прежние `document_id` станут недействительными.
3. Проверьте состояние: заново откройте документ и выполните `corel_inspect_document`, при необходимости сверьтесь с журналом задания (`corel_get_job`) и артефактами.
4. Выполните недостающие операции новыми вызовами с новыми `request_id`.
5. Сохраните дамп падения (`%LOCALAPPDATA%\Temp\kilo\CorelDRW.exe.<pid>.dmp`, где он настроен, либо отчёт WER из журнала Windows) — материалы пригодны для передачи в поддержку Corel.

## Диагностические материалы

- Дампы: `%LOCALAPPDATA%\Temp\kilo\CorelDRW.exe.38804.dmp`, `CorelDRW.exe.25556.dmp` (20.11.2026; более ранние — в том же каталоге).
- Отчёты аварийных прогонов: `artifacts/integration-hybrid/ef47876c-522a-4826-b783-bd1f21ef3495/verification.json`, `690a8aab-7092-4e5d-9752-3d762eb1a101/verification.json`; «тихое» падение — прогон `111e98fc-8319-46b5-a2ab-c7e90dfe4a84` (отчёт успешен, процесс умер после завершения).
- Журнал Windows «Приложение»: события APPCRASH `CorelDRW.exe` / `CrlFOM.dll` от 20.11.2026.

Активация гибридного режима по умолчанию заблокирована до прохождения live-гейта; этот сбой — одна из блокирующих причин.
