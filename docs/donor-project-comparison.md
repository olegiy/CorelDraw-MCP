## Вывод

Полезнее всего перенять библиотеку практических сценариев, справку по установленному API, удобные операции измерения и дополнительные варианты экспорта. Поэтому основная выгода заимствований — меньше кода в каждом запросе, меньше ошибок агента и более воспроизводимые результаты. Наличие примера или COM-метода у донора не означает наличие готового нового алгоритма у нас.

Рекомендуемый первый пакет: **независимое восстановление контекста экспорта + VBA-рецепты с общими функциями измерения + ограниченное превью выделения**. Живую интроспекцию API стоит выделить в следующий самостоятельный этап из-за сложности COM interop.

## 1. Библиотека VBA-рецептов и проверенных ограничений

**У донора:** `reference/recipes.md:6` — фигуры, цвета, текст, булевы операции, копирование, слои, группы, поиск, узлы и экспорт; `reference/pitfalls.md:41` — особенности кривых, устаревания индексов и ссылок; `reference/pitfalls.md:54` — стоимость COM-вызовов.

**У нас:** [examples](../skills/coreldraw-automation/examples/) содержит два модуля: создание геометрии и перемещение выделения. [vba.md](../skills/coreldraw-automation/references/vba.md) описывает общий контракт, но не покрывает большинство повседневных задач.

**Что перенять:** подход «одна типовая задача — небольшой исполняемый пример». Переписать выбранные рецепты на VBA: художественный текст с кириллицей; заливка CMYK/RGB и контур; дублирование с шагом; создание слоя и группировка конкретных фигур; поиск по StaticID; Weld/Trim/Intersect с получением нового StaticID; чтение узлов без ненужного преобразования исходного текста в кривые.

Каждый пример должен использовать нашу внешнюю группу Undo, проверять предусловия и возвращать измеримый JSON. Не добавлять вложенные `BeginCommandGroup`, отдельный Python runner или свои механизмы отката. При работе с группами нельзя захватывать все фигуры существующего слоя, если задача относится только к созданным объектам.

**Польза:** высокая. **Сложность:** низкая/средняя. **Очередь:** первая.

**Критерий готовности:** примеры воспроизводятся из репозитория на временном документе CorelDRAW 27; проверяются количество и StaticID объектов, размеры, типы и результат Undo там, где он значим. Ссылка донора на отсутствующий `recipes_test.py` не служит доказательством работоспособности перенесённых примеров.

Сам факт вызова `SaveSettings` ещё не доказывает восстановление каждого свойства.

**Польза:** высокая. **Сложность:** низкая/средняя. **Очередь:** вместе с рецептами.

**Критерий готовности:** один сценарий даёт одинаковые физические размеры в документах с миллиметрами и дюймами; дробные числа и кириллица дают валидный JSON при разных локалях; точка привязки и исходные настройки восстановлены и после ошибки.

## 3. Справка по установленной библиотеке типов COM

**У донора:** `server/corel.py:39` читает type library, перечисления и сигнатуры членов COM. `server/server.py:138` предоставляет инструмент `describe`.

**У нас:** [api-v27.md](../skills/coreldraw-automation/references/api-v27.md) и Context7 дают документацию API 27, но инструмента для просмотра именно установленной библиотеки типов нет.

**Что перенять:** концепцию ограниченного `corel_describe_api` с полями наподобие `type_name`, `member_filter`, `enum_name`, `offset`, `limit`. Возвращать типы параметров, optional/default, чтение/запись свойств, значения перечислений, версию и идентичность библиотеки. Рассмотреть формирование локального индекса метаданных и чтение его без доступа к рисунку.

**Что изменить относительно донора:** описывать метаданные типов, не выполнять выражения вида `doc.method()`. У донора `server/runner.py:52` используется `eval`; его перенос недопустим. Обращение к приложению для получения type library должно идти через существующий STA-исполнитель и mutex; последующие чтения готового индекса могут не занимать COM. Не обходить произвольную цепочку свойств, поскольку getter тоже может иметь последствия.

Практическую реализацию interop с `ITypeInfo/ITypeLib` для PowerShell/.NET сначала проверить отдельно. Это не основание вводить Python/pywin32 в основной продукт. Интроспекция дополняет Context7: она не объясняет все семантические ограничения и не подтверждает работоспособность экспорта.

**Польза:** высокая для редких методов. **Сложность:** средняя/высокая. **Очередь:** вторая.

**Критерий готовности:** поиск `Export`, чтение `cdrFilter` и свойств `Shape` ограничены по объёму; запросы с выражениями и вызовами отвергаются; документ, выделение и Undo не меняются; для установленной версии выдаются воспроизводимые метаданные.

## 4. Более информативная инспекция и поиск объектов

**У донора:** `server/runner.py:20` показывает точку привязки и совокупные габариты выделения; `reference/recipes.md:84` демонстрирует поиск фигур. Полноценного типизированного рекурсивного инспектора у него нет — это наше развитие идеи.

**У нас:** [Inspect-Document](../powershell/CorelAutomation.psm1:111) уже предоставляет пагинацию верхнего уровня, слои, страницы, общее количество выделенных фигур и их StaticID. Вложенные фигуры и дополнительные свойства требуют отдельного VBA-сценария.

**Что добавить по потребности:** совокупные габариты выделения в мм; `reference_point`; необязательные сведения о повороте, заливке, контуре и тексте; ограниченный поиск внутри групп с `max_depth`, лимитом посещённых объектов и явным признаком усечения. Для применения результата использовать пару `document_id` + `StaticID` и повторно проверять существование объекта перед изменением.

Текст макета запрашивать явно: его включение по умолчанию увеличит объём и раскроет содержимое рисунка клиенту. Снимок не является блокировкой документа; после изменений результаты поиска необходимо обновлять. Не превращать инспекцию в чтение всего документа одним неограниченным ответом.

**Польза:** высокая при сложных макетах. **Сложность:** средняя. **Очередь:** вторая.

**Критерий готовности:** вложенные группы доступны без потери идентичности, соблюдаются ограничения глубины/размера, неизвестный StaticID не приводит к выбору другой фигуры, пустое и большое выделение обрабатываются предсказуемо.

**Критерий готовности:** длинная сторона изображения не превышает `max_size`, показаны нужные объекты, исходное выделение/страница восстановлены, изображение находится в каталоге задания, пустое выделение диагностируется.

**У донора:** `server/sdk.py:9` содержит AI, BMP, JPG, PNG, PLT, EPS, DXF, PSD, DWG, SVG и TIFF; `export` принимает дополнительные параметры фильтра.

**Что перенять:** расширять существующий `corel_export` востребованными форматами. Следовательно, проблема подсказки «PDF через ExportEx с 1333» — направление фильтра. PDF-публикация через `PublishToPDF` в нашем проекте уже выбрана правильно.

**Польза:** зависит от производственных задач. **Сложность:** средняя для каждого формата. **Очередь:** после базового пакета.

**Критерий готовности:** справка читается клиентом без локального скилла и совпадает с ним; чтение не обращается к COM; записанная находка имеет проверяемую привязку, а не выводится из несвязанного успешного задания.

## 8. Минимальные габариты и Woodman как отдельная интеграция

**У донора:** `server/sdk.py:107` — обращения к панели, `:147` — `min_rects`, `:92` — макросы `wpanel`. Расчёт минимального прямоугольника делегирован внешнему компоненту; самого алгоритма в поставке нет.

**Что полезно:** измерять толщину и минимальные габариты повёрнутых деталей вместо обычного осевого bounding box. Это потенциально ценно для проверки мелких элементов, расхода материала и подготовки резки, но не равнозначно готовому nesting или предпечатному контролю.

Варианты: самостоятельный алгоритм по проверенной геометрической модели либо опциональный адаптер установленного Woodman. Для кривых нужна явная точность аппроксимации; минимальная ширина и прямоугольник минимальной площади — разные задачи. Выбор делать после определения реальных макетов и требуемой точности.

Панель не включать в обязательные зависимости. Для адаптера потребуются проверка версии/наличия процедур, перечень проверенных немодальных команд, точный документ, ID и срок действия заявки, подтверждение отмены/позднего результата на стороне панели. Наш mutex не координирует самостоятельные запросы сторонней панели. Одного `finally` в вызывающем процессе недостаточно для отмены уже отправленного действия.

**Польза:** высокая только для соответствующего производства. **Сложность:** высокая/неопределённая. **Очередь:** отдельное последующее исследование.

**Критерий готовности:** отсутствие Woodman не мешает основным инструментам; повёрнутые эталоны дают согласованные размеры; устаревшая заявка не меняет другой документ; неподтверждённый вызов имеет честный неопределённый исход.

## Конкретные улучшения надёжности из этого сравнения

### Приоритет 1: независимое восстановление после экспорта

[Export-Document, finally](../powershell/CorelAutomation.psm1:241) восстанавливает `PDFSettings.PublishRange`, `PageRange`, страницу и прежний активный документ в одном `try`. Если первый шаг выбросит исключение, остальные не выполнятся. Ошибка не скрыта: выставляются `cleanup.completed=false` и предупреждение. Но возможность выполнить оставшиеся шаги теряется. Удаление промежуточного файла также может само выбросить исключение.

Использовать уже имеющийся образец независимых шагов из [Invoke-Vba](../powershell/CorelAutomation.psm1:418). Сохранить первичную ошибку экспорта, собрать ошибки каждого шага очистки и попытаться восстановить остальные свойства. Проверка с подставными объектами должна намеренно ломать каждый шаг по отдельности; интеграционный сценарий должен подтвердить восстановление другого активного документа/страницы после ошибки фильтра.

Это установленное по потоку кода ограничение нашей реализации, а не воспроизведённый сбой живого CorelDRAW.

### Приоритет 1–2: регрессионные сценарии сохранности документа

Перенять из раздела 15 чужого анализа именно сценарии: пустое выделение; заблокированный слой; ошибка до первого изменения; частичное изменение перед runtime error; ошибка JSON после изменения; смена активного документа; отдельный отказ каждого шага cleanup. Проверять, что существовавшая до задания фигура остаётся на месте и не отменяется автоматикой.

Для Undo использовать только созданный тестом документ и собственное предыдущее действие-маркер. Не создавать намеренное зависание и не завершать пользовательский CorelDRAW ради проверки. Синтетические тесты таймаута и потери исполнителя у нас уже есть; они не доказывают поведение истории Undo приложения.

Отдельно проверить отказ канала прогресса: [Invoke-Vba](../powershell/CorelAutomation.psm1:414) начинает `finally` с `Set-Stage 'cleanup'`; [Set-Stage](../powershell/CorelAutomation.psm1:15) вызывает callback, а тот пишет в stdout в [worker.ps1](../powershell/worker.ps1:19). Исключение записи способно прервать выполнение до независимых шагов восстановления. Это статически найденный сценарий, ещё не воспроизведённый. Сообщение о стадии должно быть вспомогательным: подставной callback, выбрасывающий ошибку, не должен препятствовать cleanup.

### Приоритет 2: безопасный переносимый диагностический отчёт

Идея локального отчёта полезна для сопровождения, но у нас уже есть подробные артефакты каждого задания. Добавлять следует отдельный **краткий файл для передачи**, а не ещё один полный журнал.

Включать по разрешённому списку версию сервера/Corel/PowerShell, стадии, код ошибки, признаки cleanup и технические итоги. По умолчанию исключать VBA-код, тексты макета, пути, имена документов, произвольный `result` и request_id с пользовательским содержимым. Для корреляции использовать отдельный технический ID; не обещать, что регулярные выражения гарантированно обезличат произвольный текст. Расширенные детали включать явно. Уникальное имя и атомарная запись исключают перезапись предыдущего отчёта.

Проверки: синтетические секреты, относительные/абсолютные пути и кириллица не проходят в краткий отчёт; повторный экспорт создаёт новый файл; ошибки записи видимы. Отправка кому-либо — отдельное действие пользователя, не часть генерации.

### Приоритет 2: квоты и уборка с сохранением идемпотентности

Сейчас артефакты сохраняются до ручного удаления, что прямо описано в README. Полезно добавить просмотр объёма и возраста, предварительный список кандидатов и явно запускаемую очистку старых завершённых артефактов. Это развитие идеи `purge` донора, а не перенос его политики «30 дней».

**Нельзя просто удалять каталоги старых заданий:** в [JobManager.submit](../src/jobs.ts:47) наличие каталога и отчёта защищает от повторного исполнения request_id. После полного удаления прежний ID снова выглядит новым. Перед автоматической уборкой нужен отдельный долговечный реестр `request_id`/fingerprint/исхода либо компактная запись, запрещающая повтор, с явным контрактом срока хранения. Коллизии аргументов тоже должны оставаться обнаружимыми.

Активные, `timed_out`, `unknown` и непроверенные диагностические задания не должны попадать под обычную очистку. Критерий готовности: большой preview/GMS удалён, но повтор исходного request_id не запускает мутацию, конфликт параметров отвергается, текущая операция и пользовательские файлы не затронуты.

## Что не переносить

- Произвольные выражения в справочном `describe`, новый Python-исполнитель и автоматический выбор документа по имени/активности.
- Обещание транзакционного отката произвольного VBA, автоматический `Undo` после таймаута и уничтожение CorelDRAW как восстановление.
- Операцию `undo(steps)` без привязки к проверенному заданию: она может отменить ручную работу пользователя. Для нынешнего продукта достаточно существующей группы и явного описания обычной отмены в GUI.
- Неограниченный DPI, произвольные параметры фильтров и копирование чужой таблицы API без проверки версии и направления import/export.
- Обязательный Woodman, общий реестровый канал панели без протокола завершения/отмены и изменение установленных GMS-проектов.
- Эвристику «следующий успех исправил предыдущую ошибку», перезаписываемые отчёты, обещание полного обезличивания и скрытые ошибки журнала.

У донора в поставке не найден отдельный файл лицензии. Для распространения буквальных фрагментов кода/текстов необходимо установить права на них; до этого рекомендации ориентированы на самостоятельную реализацию идей в нашей архитектуре.
